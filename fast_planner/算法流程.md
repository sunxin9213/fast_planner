# Fast-Planner 算法流程梳理

Fast-Planner 是香港科技大学 Aerial Robotics Group 开发的多旋翼无人机快速规划器，核心思想是**"前段搜索 + 后段优化"**：先通过启发式搜索得到一条可行的动力学轨迹，再通过 B 样条参数化，在梯度优化的框架下得到平滑、安全、动力学可行的轨迹。

本文档梳理两条完整算法链路：

1. **局部重规划（Kinodynamic Replanning）** —— 核心方案，基于 Kinodynamic A* + B 样条优化。
2. **拓扑重规划（Topological Replanning）** —— 增强方案，基于拓扑 PRM + B 样条优化。

---

## 一、系统总体架构与模块划分

| 模块目录 | 主要文件 | 作用 |

| `path_searching` | `astar.cpp`、`kinodynamic_astar.cpp`、`topo_prm.cpp` | 路径搜索：几何 A*、动力学 A*、拓扑 PRM |

| `plan_manage` | `planner_manager.cpp`、`kino_replan_fsm.cpp`、`topo_replan_fsm.cpp`、`traj_server.cpp` | 顶层管理：规划任务调度与轨迹发布 |
| `traj_utils` | `planning_visualization.cpp` | 规划结果的可视化（Rviz） |

```

       ↑

       ↑

       ↑

       ↑

       ↑

```

## 二、环境表示层：ESDF 距离场

**入口**：`plan_env/src/sdf_map.cpp`、`edt_environment.cpp`

无人机需要在优化中快速判断"某位置离障碍物有多远"，因此 Fast-Planner 把传统栅格地图转换为 **ESDF（Euclidean Signed Distance Field，欧氏带符号距离场）**。`F(x) > 0` 表示到最近障碍物的距离，`F(x) < 0` 表示在障碍物内部。

**算法流程**：

1. **栅格占用更新**：激光/深度点云经 `raycast`（光线投射），把传感器数据写入体素地图，更新每个体素为 occupied / free / unknown。
2. **ESDF 计算**：基于当前占用地图，用扫描算法逐步膨胀，迭代得到每个 free 体素到最近 occupied 体素的距离，写入 `sdf_map_->edt_buffer_`。
3. **查询接口**：`edt_environment_` 提供 `evaluateCoarseEDT()`（粗分辨率快速查询）、`evaluateEDT()`（精确查询）、`getDistance()` 等接口，后续的 A* 碰撞检测与 B 样条距离代价都基于它。

> 这一层是"安全代价快速评估"的基础，也是整个规划器能够实时运行的关键。

## 三、局部重规划链路（核心）

### 3.1 顶层调度：有限状态机 `kino_replan_fsm.cpp`

FSM 用一个状态机驱动重规划，典型状态：

- `WAIT_TARGET`：等待用户发布目标点。
- `GEN_NEW_TRAJ`：收到目标，调用 `planManager_->kinodynamicReplan()` 生成新轨迹。
- `EXEC_TRAJ`：执行当前轨迹，同时周期性 `checkCollision()`，若未来轨迹有碰撞风险则回退到 `REPLAN` / `GEN_NEW_TRAJ`。
- `REPLAN`：轨迹被判定即将碰撞时，以当前状态为起点重新规划。

**核心流程**（对应 3.2）：

```
新目标到来 or 检测到碰撞风险
   ↓
[fsm] load new target
   ↓
[planner_manager] kinodynamicReplan()
```

### 3.2 核心入口 `kinodynamicReplan()`

`plan_manage/src/planner_manager.cpp`

```
输入：起始位姿 + 速度 + 加速度，以及目标位置、速度
   ↓ ① 判断是否已接近目标
   ↓ ② 调用 kino_path_finder_->search()   （Kinodynamic A* 搜索）
   ↓ ③ 把搜索得到的路径采样并参数化为 B 样条
   ↓ ④ 调用 bspline_optimizers_[0]->BsplineOptimizeTraj()（梯度优化）
   ↓ ⑤ 迭代时间调整 reallocateTime()      （满足速度/加速度限制）
   ↓
输出：local_data_.position_traj_（优化的 B 样条轨迹）
```

---

### 3.3 Kinodynamic A* 路径搜索（kinodynamic_astar.cpp）

与普通 A* 相比，Kinodynamic A* 考虑**动力学约束**，状态空间由：

```
状态 = [位置(3维), 速度(3维)]   = 6 维状态
```

而不是只搜几何路径。算法输入起始状态（位置/速度/加速度）与目标状态，输出满足加速度约束的可行动力学路径。

**搜索主流程 `search()`**：

1. **状态池分配**：从节点池 `path_node_pool_` 取起点，初始化 `g_score=0`。
2. **启发式 `estimateHeuristic()`**：估计算法采用动力学感知的启发式（如恒定加速度假设下到达目标的最小代价），保证搜索有界且高效。
3. **状态扩展**：
   - 对每个弹出节点，在当前位置采样多个**加速度方向控制输入**；
   - 用**四元数/双积分模型**在固定时间步长内推进，求末端位置与速度；
   - 检查新状态是否碰撞（用 ESDF），计算代价 `g_score`。
4. **开放集循环**：优先扩展 `f = g + h` 最小的节点，直到找到接近目标的节点。
5. **Shot 轨迹 `computeShotTraj()`**：一旦扩展节点接近终点，尝试用一条多项式直接连接两状态（"shooting"），若全程无碰撞则直接收敛，避免穷举。
6. 返回 `KINO_PATH / NO_PATH / REACH_END` 等状态码。

**输出**：`getKinoTraj()` 返回高频采样的动力学轨迹，`getSamples()` 提供等时间间隔的点集与起止导数，用于 B 样条参数化。

---

### 3.4 B 样条参数化（non_uniform_bspline.cpp）

`parameterizeToBspline()` 把 Kinodynamic A* 的点集拟合成一条**均匀 B 样条**：

```
点集 point_set + 起止速度/加速度 → 反算控制点 ctrl_pts
```

- 保留起点速度、加速度与终点速度作为边界导数约束（与搜索路径平滑衔接）；
- 为绕过"控制点个数"约束，通常强制设置一定的规格化，使 B 样条精确通过给定采样点或保持其形态；
- `NonUniformBspline` 类封装了：
  - `evaluateDeBoor()`：De Boor 递推求 B 样条上一点（可求任意阶导数）；
  - `getDerivative()`：对 B 样条求导（速度/加速度曲线也是低阶 B 样条）；
  - `checkFeasibility()`：检查速度、加速度是否超出物理限制；
  - `reallocateTime()`：迭代调整节点时间间隔，把最大速度/加速度拉回限制内。

---

### 3.5 B 样条梯度优化（bspline_optimizer.cpp）

`BsplineOptimizeTraj()` 是"后段优化"核心，用 NLopt 对控制点做无约束梯度优化。代价函数用**位掩码位**组合：

| 常量 | 位 | 含义 |
| --- | --- | --- |
| `SMOOTHNESS` | bit 0 | 平滑度（最小化加加速度 `|| jerk ||²` 的积分） |
| `DISTANCE` | bit 1 | 安全（惩罚控制点侵入障碍区域，基于 ESDF） |
| `FEASIBILITY` | bit 2 | 动力学可行（把速度/加速度拉回限制） |
| `ENDPOINT` | bit 3 | 端点约束（贴近 A* 终点） |
| `GUIDE` | bit 4 | 引导路径（贴近初始路径） |
| `WAYPOINTS` | bit 6 | 路标点约束 |

典型组合：

- `GUIDE_PHASE = SMOOTHNESS | GUIDE`：引导阶段（先保证大致形状）。
- `NORMAL_PHASE = SMOOTHNESS | DISTANCE | FEASIBILITY`：正常阶段，核心三项。

**优化流程**：

1. 计算各代价对应的**解析梯度**：
   - `calcSmoothnessCost()`：速度/加加速度的差分得到平滑度梯度；
   - `calcDistanceCost()`：利用 ESDF 距离及其梯度，惩罚离障碍太近的控制点；
   - `calcFeasibilityCost()`：超出最大速度/加速度的控制点受益率惩罚。
2. NLopt L-BFGS 迭代更新控制点，`max_iteration_num` 控制迭代次数。
3. 迭代多轮（`max_num_id`）提高收敛质量。

*相关论文与脚本参考 `bspline_opt/script/calc_jacobian.py`、`cost_function.py`，用于推导代价的雅可比。*

---

### 3.6 迭代时间调整（reallocateTime）

优化后的轨迹可能仍不满足速度/加速度限制，因此：

```
while (!feasible && 迭代次数<3) :
     pos.reallocateTime()      # 按比例拉伸/压缩节点时间
     feasible = pos.checkFeasibility()
```

通过拉伸总时长来降低最大速度/加速度，直至满足限制，最终得到 `local_data_.position_traj_`。

---

### 3.7 轨迹跟踪指令生成（traj_server.cpp）

`traj_server` 订阅优化后的 B 样条轨迹，以设定频率：

1. 用 `evaluateDeBoor()` 计算当前位置、速度、加速度；
2. 叠加 PD 前馈：`position_cmd`、`velocity_cmd`、`acceleration_cmd`；
3. 通过 `quadrotor_msgs::PositionCommand` 发布给底层控制器；
4. 同时支持 yaw 轨迹控制（`traj_server.cpp` 中的 yaw 控制逻辑）。

## 四、拓扑重规划链路

适用场景：需要在多个"同伦类"路径中选择最优者，或者在狭窄/复杂环境中提供更优的全局参考。它引入了**拓扑等价类（同伦类）**概念，保证搜到的多条路径拓扑互不相同。

### 4.1 全局参考轨迹生成 `planGlobalTraj()`

`planner_manager.cpp`

```
输入：全局路标点 global_waypoints_
   ↓ 把过远的路标中间插点（距离 > 4.0 则细分）
   ↓ 生成一条全局参考路径
   ↓ 存入 plan_data_.global_path
```

### 4.2 拓扑 PRM 搜索 `topo_prm.cpp`

**核心增量**：在普通 PRM（概率路标图）基础之上，把"简单剪枝"替换为**基于同伦（Homotopy）类判别**的剪枝，从而生成多条拓扑不同的备选路径。

**流程 `findTopoPaths()`**：

1. **路径采样与图构建**：在起始与目标之间按拓扑抽样（`sample_inflate_x/y/z` 控制采样范围），构建路标图 `graph_`。
2. **同伦判别与剪枝**：对每条候选路径计算与参考路径的"环绕/包围"关系，同伦类相同的路径合并保长度最优，异类路径全部保留（`reserve_num_`、`ratio_to_short_` 参数控制保留策略）。
3. **捷径优化 `shortcut()`**：对保留路径做 `short_cut_num_` 次局部缩短，使之更短更平滑。
4. **输出候选拓扑路径** `topo_paths_`：一组（通常 2~4 条）拓扑不同的路径。

### 4.3 拓扑路径下的轨迹优化

对每条拓扑候选路径分别：

1. 把路径采样点参数化为 B 样条（`parameterizeToBspline`）；
2. 使用 `BsplineOptimizeTraj`（含 `GUIDE` / `WAYPOINTS` 代价）优化；
3. 从中选出综合最优的一条作为当前局部轨迹。

## 五、yaw 角规划

在 `planner_manager` / `traj_server` 中：

- 速度方向作为参考，规划 yaw 沿轨迹平滑变化；
- `traj_server` 内部维护 `last_yaw_`、`time_forward_` 等变量做增量平滑，避免 yaw 突变。

## 六、关键参数（config）

配置位于 `plan_manage/config/*.rviz` 与 launch 中，核心参数：

| 参数 | 含义 |
| --- | --- |
| `manager/max_vel` / `max_acc` / `max_jerk` | 速度、加速度、加加速度物理限制 |
| `manager/dynamic_environment` | 是否动态环境（是否考虑动态障碍物预测） |
| `manager/clearance_threshold` | 安全距离阈值 |
| `manager/control_points_distance` | 控制点间距（决定时间步 `ts`） |
| `bspline_optimizer/lambda1~8` | 各代价权重 |
| `bspline_optimizer/dist0` | 距离代价的软边界 |
| `kinodynamic_astar/*` | 搜索参数 |
| `topo_prm/*` | 拓扑采样与剪枝参数 |

## 七、总结：核心思想一句话

> **"前段动力学搜索给形状，后段 B 样条梯度优化给平滑、安全与动力学可行，ESDF 保证实时距离评估。"**

两条链路的差别在于"前段搜索"：

- **Kinodynamic 局部重规划**：随时以当前状态重搜一条最优动力学路径，适合未知 / 动态环境的快速反应。
- **拓扑重规划**：离线/全局给出多条拓扑不同的粗轨迹，优化时择优，适合复杂静态环境的全局引导。

而 `plan_manage/src/traj_server.cpp` 负责把最终的 B 样条轨迹实时转换成底层控制器可执行的期望状态指令。
